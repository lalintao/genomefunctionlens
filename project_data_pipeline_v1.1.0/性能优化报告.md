# project_data Pipeline 1.1 性能优化报告

优化日期：2026-10-21

## 1. 结论

同一份完整 10,122-genome 输入：

```text
1.0 基线：约 1,071 秒（17 分 51 秒）
1.1 优化：约   844 秒（14 分 04 秒）
节省：约       227 秒（3 分 47 秒）
提速：约       21.2%
```

优化后运行期数据与基线完全一致：

- 13 张 SQLite 表逐行一致
- `protein` 18,769,129 行一致
- `protein_annotation` 39,116,899 行一致
- 4 个 Parquet 矩阵 schema 和数据一致
- SQLite integrity、索引和查询计划一致

## 2. 优化内容

### 2.1 annotation 单进程直写 SQLite

旧流程：

```text
annotation TSV
  -> 多个 annotation Parquet chunk
  -> 读取全部 chunk
  -> annotation_hits.sqlite
```

新流程：

```text
annotation TSV
  -> annotation_hits.sqlite（单进程直接批量写入）
```

多进程模式仍保留 Parquet 分片，但默认 `workers=1` 不再产生 annotation Parquet 中继。

### 2.2 移除中间层无用字段

`annotation_hit_stage`、annotation Parquet 和 worker 返回行中都移除了未使用的 `protein_id`。

该字段只用于查找阶段，后续所有表都通过 `protein_key` 和 `genome_id` 工作。

### 2.3 压缩蛋白查找表

旧结构：

```text
protein_id -> (genome_id, protein_key)
```

新结构：

```text
protein_id -> packed_int
packed_int = (genome_id << 32) | protein_key
```

同时移除了单进程模式下对 1,876 万项字典的再次复制。

### 2.4 最终 SQLite 批量写入

- 使用 `journal_mode=OFF`
- 使用 `synchronous=OFF`
- 使用 `temp_store=MEMORY`
- 512 MiB page cache
- 2 GiB mmap window
- staged 表按整表事务写入，而不是每个 chunk 自动 commit
- 索引在数据写完后统一创建
- `ANALYZE` 使用 `analysis_limit=1000` 近似统计

### 2.5 分阶段计时

`manifest.json.build_performance.timing_seconds` 现在记录：

```text
prepare_inputs
stage_proteins
parse_annotations
build_annotation_tables
build_protein_annotation
write_tree_core
build_matrices
write_runtime_sqlite
total
```
