# project_data Pipeline 1.0 审查报告

审查日期：2026-10-20

## 1. 审查范围

本次审查对象是当前最新的完整 `project_data` 构建链：

```text
run_pipeline.py
  -> webdb_pipeline.cli
  -> webdb_pipeline.pipeline
  -> webdb_pipeline.runtime_package
  -> SQLite / Parquet / tree_core / manifest
```

同时检查了输入发现、row_data 审计、annotation 并发解析、索引创建和现有测试。

## 2. 已确认并修复的问题

| 等级 | 问题 | 修复 |
| --- | --- | --- |
| 高 | `audit-row-data` 会检查所有 genome database 目录，但构建只检查被树映射引用的目录，导致旧目录使审计失败 | 审计改为只检查被引用数据库；未引用目录降为 warning |
| 高 | annotation 按字节分片时，如果分片边界正好落在行首，worker 会跳过完整记录 | 分片起点的前一字节先探测换行，新增边界测试 |
| 高 | `--force` 在输入校验前删除旧输出，输入错误会破坏已有产物 | 先发现并校验输入，再处理 output-root |
| 中 | 默认并发会根据 CPU 自动放大，但每个 annotation worker 会复制大型蛋白查找表 | 默认 `--workers` 改为 `1`，文档明确内存风险 |
| 中 | manifest 声称 FASTA 并行读取，实际 `.faa` 始终顺序读取 | 改为 `parallel_fasta_reader=false` 并增加读取策略字段 |
| 中 | 多树构建时运行期说明只复制到 output-root，不进入各子包 | 改为复制到每个 package root |
| 中 | module completeness 未检查重复 accession、空 accession 和列缺失，可能生成错行矩阵 | 增加输入一致性和行数校验 |
| 低 | CLI 和文档仍推荐 `--workers 4`，与内存风险不一致 | 文档、帮助文本和示例统一为 `1` |

## 5. 剩余风险

1. 构建不是原子发布：进程在写最终目录时中断，可能留下不完整 `project_data`
2. `--workers > 1` 仍会让每个进程持有蛋白查找表副本，完整大库需要按机器内存谨慎配置
3. 完整 10,122-genome 输入本轮只做了审计，没有重新跑完约 9 GB 的完整构建；现有历史构建日志显示完整构建曾成功
4. `update_project_data_indexes.py` 和 `runtime_indexes.py` 的索引定义存在重复，后续版本应合并为单一来源
5. 运行期 `taxonomy` 表仍是下载 header 的过渡设计
