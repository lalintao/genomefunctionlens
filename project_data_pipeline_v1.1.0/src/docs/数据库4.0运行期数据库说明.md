# 数据库 4.0 运行期数据库说明

本文描述当前 4.0 运行期数据包中的目录结构、SQLite schema 和关键约束。

## 1. 运行期数据包结构

```text
project_data/
  数据库4.0运行期数据库说明.md
  backend_ready/
    manifest.json
  database/
    web_database.sqlite
  processed/
    tree_core/
      tree_core.bin
      {species_tree}.tre
    matrices/
      cog.parquet
      kegg.parquet
      pfam.parquet
    module_completeness/
      module_completeness.parquet
```

说明：

- `web_database.sqlite`：运行期主数据库
- `数据库4.0运行期数据库说明.md`：随包提供的运行期 schema 说明
- `tree_core.bin`：前端一次性加载的紧凑树文件，格式为 `gzip + compact json`
- `processed/matrices/*.parquet`：annotation 热图矩阵，行顺序严格等于 `genome_id ASC`
- `processed/module_completeness/module_completeness.parquet`：module 完整度矩阵，行顺序同样严格等于 `genome_id ASC`
- `manifest.json`：运行期入口清单
- `manifest.json.build_performance`：记录本次构建的并发参数、annotation chunk 参数和分阶段耗时
- `manifest.json.build_performance.timing_seconds`：记录 `prepare_inputs`、`stage_proteins`、`parse_annotations`、`write_runtime_sqlite` 等阶段耗时
- `manifest.json.build_performance.annotation_dispatch_strategy`：记录 annotation 的单进程直写或多进程分片策略
- `manifest.json.build_performance.staging_dir`：记录本次构建使用的临时目录
- `manifest.json.build_performance.staging_dir` 指向的是构建期暂存目录，不属于运行期数据包内容

## 2. SQLite 表

### 2.1 `tree_node`

保存树结构本体。

字段：

- `node_id`
- `parent_id`
- `node_in`
- `node_out`
- `rank`
- `is_leaf`
- `branch_length`
- `cumulative_branch_length`

说明：

- `node_in/node_out` 是全节点 DFS 区间
- `rank` 仅保存该节点作为命名 taxon 根时的最深 rank，供兼容显示；完整的多 rank 命名关系以 `tree_named_taxon_index` 为准。
- 原始叶子节点 `is_leaf = 1`

### 2.2 `tree_named_taxon_index`

保存所有命名 taxon 节点。

字段：

- `rank`
- `taxon_name`
- `taxon_name_norm`
- `node_id`

用途：

- rank 搜索
- 条带和分类名展示
- taxonomy 节点 id 反查名字

### 2.3 `genome`

保存 genome 实体、筛选字段，以及树叶和矩阵行绑定关系。

字段：

- `genome_id`
- `leaf_node_id`
- `genome_database`
- `genome_accession`
- `genome_name`
- `if_refseq`
- `checkm2_completeness`
- `checkm2_contamination`
- `quality_score`
- `contig`
- `species_genome_count`
- `source`
- `source_version`
- `protein_key_start`
- `protein_key_end_exclusive`

关键约束：

- `genome_id` 必须是 `0-based`、连续、稳定、无空洞的 dense id
- 所有 annotation matrix 和 module completeness matrix 都必须严格按 `genome_id ASC` 构建行顺序
- `leaf_node_id` 必须唯一
- `leaf_node_id` 直接对应 species rank 叶子节点
- `genome_id` 同时承担主键和矩阵行号语义

运行期不再保留：

- `leaf_label`
- `leaf_order_index`
- `matrix_row_index`
- `is_cultured`

### 2.4 `taxonomy`

当前版本保留，用于下载 header 组装。

字段：

- `node_id`
- `domain`
- `phylum`
- `class_name`
- `order_name`
- `family`
- `genus`
- `species`

说明：

- `node_id` 对应叶子节点 id，也就是 `genome.leaf_node_id`
- `domain/phylum/.../species` 保存的不是名字，而是对应命名 taxon 的 `node_id`
- 真实名字要去 `tree_named_taxon_index` 里反查

### 2.5 `matrix_file`

保存所有运行期矩阵的路径信息，annotation matrix 和 module completeness matrix 已统一到这一张表里。

字段：

- `matrix_kind`
- `genome_database`
- `annotation_type`
- `matrix_path`
- `matrix_format`
- `row_count`
- `column_count`
- `value_type`

字段语义：

- `matrix_kind`
  - `annotation`
  - `module_completeness`
- `annotation_type`
  - annotation 矩阵时为 `cog / kegg / pfam`
  - module 完整度矩阵时固定为 `module`

### 2.6 `tree_dataset`

保存当前数据包的树级元信息。

字段：

- `species_tree`
- `genome_database`
- `tree_file`
- `tree_newick_path`
- `tree_core_path`
- `tree_core_format`
- `node_count`
- `leaf_count`
- `genome_count`

### 2.7 注释字典表

4.0 不再保留通用 `annotation / annotation_meta_*` 兼容层，直接拆成独立字典表：

- `cog_annotation`
- `pfam_annotation`
- `kegg_annotation`
- `module_annotation`

前三者公共字段：

- `annotation_id`
- `annotation_value`
- `short_name`
- `full_name`
- `source`
- `source_version`
- `extra_json`
- `search_text`

`module_annotation` 额外字段：

- `module_class`
- `module_category`
- `module_subcategory`
- `description`

### 2.8 `module_kegg_member`

保存每个 module 对应的 KO id 有序数组。

字段：

- `module_annotation_id`
- `kegg_annotation_ids_json`

说明：

- `kegg_annotation_ids_json` 是按既定顺序排列的 `kegg_annotation.annotation_id` 数组
- 数组顺序直接承担前端展开 module KO 列表时的稳定顺序语义
- 运行期不再单独保存 `member_order / step_index / step_logic / is_optional`

### 2.9 `protein`

保存蛋白本体。

字段：

- `protein_key`
- `genome_id`
- `protein_id`
- `protein_name`
- `sequence`
- `sequence_length`

说明：

- 序列正文已经直接并入 `protein`
- 不再保留 `protein_sequence`

### 2.10 `protein_annotation`

保存蛋白命中的 annotation。

字段：

- `annotation_hit_id`
- `annotation_type`
- `annotation_id`
- `genome_id`
- `protein_key`

说明：

- `annotation_id` 指向对应类型的独立字典表
- `genome_id` 是有意冗余，用于下载和过滤时减少 join

## 3. 运行期不再保留的内容

运行期数据包中不再保留：

- `tree_leaf`
- `tree_node.left_index / right_index / label / leaf_count`
- `genome.leaf_label / leaf_order_index / matrix_row_index / is_cultured`
- `protein_sequence`
- `taxon_representative`
- `module_completeness_file`
- `processed/tree_index/**`
- `processed/species_tree/**`
- `processed/registry/**`
- `processed/reports/**`
- `processed/tables/**`
- `raw/input_sources.json`

## 4. 关键一致性约束

### 4.1 节点 id 一致

以下对象中的 `node_id` / `leaf_node_id` 必须一致：

- `tree_node.node_id`
- `tree_named_taxon_index.node_id`
- `genome.leaf_node_id`
- `taxonomy.node_id`
- `tree_core.bin`

### 4.2 矩阵行一致

以下都必须使用同一行顺序：

- `genome.genome_id`
- `processed/matrices/*.parquet`
- `processed/module_completeness/module_completeness.parquet`

硬约束：

```text
matrix row i <-> genome.genome_id = i
```

也就是说，矩阵文件不能再依赖单独的 `leaf_order` 或 `matrix_row_index` 做对齐。

### 4.3 taxonomy 字段语义

`taxonomy.domain/phylum/.../species` 存的是命名 taxon 节点 id，不是原始名字。

## 5. tree_core.bin 内容

`tree_core.bin` 内部是 `gzip + compact json`，核心数组包括：

- `parent`
- `node_in`
- `node_out`
- `rank_id`
- `is_leaf`
- `branch_length`
- `cumulative_branch_length`
- `leaf_name_id`
- `taxon_name_id`
- `children_offsets`
- `children_pool`
- `named_taxa_rank_id`
- `named_taxa_node_id`
- `named_taxa_name_id`

这样前端加载一次后，就能在内存里完成：

- 展开/折叠
- rank 全局展开
- 命名 taxon 查找
- 条带分组

不再依赖旧式 `tree.json / index.json / leaf_order.json / metadata.tsv`。
