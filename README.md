# GenomeFunctionLens Local

GenomeFunctionLens Local (`genomefunctionlens_local`) is a single-user, local scientific data application for Windows. It supports browsing and querying microbial genome functional annotations, with linked exploration across species trees and heatmaps.

The application supports COG, KEGG, Pfam, and KEGG Module queries, result visualization, table and image export, saved queries, and sequence downloads. Scientific data is generated by the companion `project_data` pipeline and is not included in the source repository.

> **Note:** This repository does not include `project_data/`. Before the first launch, build the data with the pipeline or provide an existing `project_data` directory.

## Features

- Browse genome functional annotation results by dataset.
- Query COG, KEGG, Pfam, and KEGG Module annotations.
- Explore species trees and heatmaps interactively.
- Filter results by taxonomic scope and customize tree and heatmap styles.
- Export results as SVG, PNG, PDF, or data tables.
- Save queries and manage local query records.
- Download protein sequences and monitor progress through a built-in job queue.
- Store saved queries and download state in local JSON files without an external database.

## Quick start

### 1. Prepare `project_data`

GenomeFunctionLens Local does not include scientific data. A single-tree package should contain:

```text
project_data/
├── 数据库4.0运行期数据库说明.md
├── backend_ready/
│   └── manifest.json
├── database/
│   └── web_database.sqlite
└── processed/
    ├── tree_core/
    │   ├── tree_core.bin
    │   └── {tree_dir}.tre
    ├── matrices/
    │   ├── cog.parquet
    │   ├── kegg.parquet
    │   └── pfam.parquet
    └── module_completeness/
        └── module_completeness.parquet
```

To build `project_data` from raw inputs, see [Build project_data](#build-project_data).

### 2. Start the application

From the repository root, double-click:

```text
start_local_web.bat
```

Or start it from PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy_local_web.ps1 `
  -ProjectDataRoot "D:\datasets\my_project_data"
```

The launcher automatically:

1. Creates a local Python virtual environment.
2. Installs backend dependencies on first launch.
3. Validates the manifest, SQLite database, tree core, and matrices.
4. Creates the local runtime data directory.
5. Starts the web service and download worker.
6. Opens `http://127.0.0.1:8000/` in the browser.

If `project_data` is located in one of the following paths, `-ProjectDataRoot` can be omitted:

```text
genomefunctionlens_local_v1.0/project_data/
project_data/
../project_data/
```

### 3. Launcher options

| Option | Default | Description |
| --- | --- | --- |
| `-ProjectDataRoot` | Auto-detected | Path to a concrete runtime data package |
| `-Port` | `8000` | Local web service port |
| `-BindAddress` | `127.0.0.1` | Network address to bind |
| `-NoBrowser` | Disabled | Do not open the browser automatically |
| `-Reinstall` | Disabled | Reinstall Python dependencies |
| `-PythonExecutable` | Auto-detected | Path to a specific Python interpreter |

Examples:

```powershell
# Use another port
powershell -ExecutionPolicy Bypass -File .\deploy_local_web.ps1 `
  -ProjectDataRoot "D:\my_project_data" `
  -Port 8080

# Do not open the browser
powershell -ExecutionPolicy Bypass -File .\deploy_local_web.ps1 `
  -ProjectDataRoot "D:\my_project_data" `
  -NoBrowser

# Reinstall dependencies
powershell -ExecutionPolicy Bypass -File .\deploy_local_web.ps1 `
  -ProjectDataRoot "D:\my_project_data" `
  -Reinstall
```

To start from the application directory instead:

```powershell
cd genomefunctionlens_local_v1.0
.\start_local.bat
```

## Build project_data

The companion pipeline reads raw inputs from `row_data/` and writes runtime packages to `project_data/`.

### Install the pipeline

Windows PowerShell:

```powershell
cd project_data_pipeline_v1.1.0
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -e .
```

Linux or macOS:

```bash
cd project_data_pipeline_v1.1.0
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -e .
```

Pinned dependency information is available in `requirements-lock.txt`, `environment.yml`, and `pyproject.toml`.

Each line in the species tree mapping file defines one mapping:

```text
{tree_dir} : {genome_database}
```

Example:

```text
GTDB226 : archaea226
```

Only genome databases referenced by the mapping file are included in the build.

### Audit raw inputs

Run the audit before building:

```powershell
python run_pipeline.py audit-row-data `
  --workspace F:\path\to\workspace `
  --mode deep
```

Exit codes:

- `0`: no errors; the build can continue.
- `1`: validation errors were found; fix them before building.

`fast` mode checks directories, schemas, tree leaf alignment, genome mappings, and completeness alignment. `deep` mode also parses KEGG Module source files.

To compare annotation `protein_id` values with FASTA records:

```powershell
python run_pipeline.py audit-row-data `
  --workspace F:\path\to\workspace `
  --mode deep `
  --scan-annotation-proteins
```

This option scans all FASTA and annotation files and is significantly slower.

### Build the runtime package

Windows PowerShell:

```powershell
python run_pipeline.py build `
  --workspace F:\path\to\workspace `
  --output-root F:\path\to\workspace\project_data `
  --temp-root F:\path\to\workspace\temporary_file\build_stage `
  --workers 1 `
  --annotation-chunk-rows 250000 `
  --force
```

Linux or macOS:

```bash
python run_pipeline.py build \
  --workspace /path/to/workspace \
  --output-root /path/to/workspace/project_data \
  --temp-root /path/to/workspace/temporary_file/build_stage \
  --workers 1 \
  --annotation-chunk-rows 250000 \
  --force
```

| Parameter | Default | Description |
| --- | --- | --- |
| `--workspace` | Current directory | Workspace root |
| `--output-root` | `<workspace>/project_data` | Runtime package output directory |
| `--temp-root` | `<workspace>/temporary_file/build_stage` | Chunk and staging directory |
| `--workers` | `1` | Number of annotation TSV parser processes |
| `--annotation-chunk-rows` | `250000` | Rows per streaming annotation chunk |
| `--force` | Off | Remove the existing output directory and rebuild |

> **Warning:** `--force` removes the existing `--output-root` before rebuilding. Verify the path before running the command.

Each annotation worker creates its own copy of the protein lookup table. For large databases, start with `--workers 1`. The `--workers` option does not control FASTA read concurrency.

### Validate the build

Check that the required files exist:

```powershell
Test-Path project_data\backend_ready\manifest.json
Test-Path project_data\database\web_database.sqlite
Test-Path project_data\processed\tree_core\tree_core.bin
Test-Path project_data\数据库4.0运行期数据库说明.md
```

Run the pipeline tests:

```powershell
cd project_data_pipeline_v1.1.0
python -m pytest
```

Before using a package, confirm that:

- SQLite `PRAGMA integrity_check` returns `ok`.
- Every matrix shape matches `row_count` and `column_count` in the manifest.
- Every matrix has the same number of rows as the `genome` table.
- `manifest.json` contains `pipeline_version: "1.1.0"` and `schema_version: "4.0"`.

### Runtime data constraints

- The runtime schema does not contain `tree_leaf`.
- `genome.leaf_node_id` links rows to species-rank leaf nodes.
- `genome.genome_id` is a dense, stable, zero-based identifier without gaps.
- Annotation and module completeness matrices are ordered by `genome_id ASC`.
- `module_completeness_file` is merged into `matrix_file`.
- `module_kegg_member` stores only `module_annotation_id` and `kegg_annotation_ids_json`.

## Security and scope

GenomeFunctionLens Local is a single-user, local-only application.

- It does not provide login, accounts, roles, or multi-user isolation.
- Saved queries and download tasks are not separated by user.
- The server listens on `127.0.0.1` by default.
- It does not provide authentication or download authorization tokens.

Do not bind the service to `0.0.0.0` or expose it to an untrusted network without additional firewall and network isolation.
