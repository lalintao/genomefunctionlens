# 服务器蛋白与注释覆盖率统计

将 `count_protein_annotation_coverage.py` 单独上传服务器即可。Python >= 3.9，仅使用标准库，无需安装流水线、pandas 或 Biopython；只读原始数据。

```bash
python3 count_protein_annotation_coverage.py \
  --workspace /share/cn1_fs/project/LLT/GTDB_arc_bac_232 \
  --output-dir ./protein_coverage_report \
  --temp-dir /path/to/local/scratch
```

替换实际 workspace 和 scratch 路径。`--temp-dir` 可省略，使用系统临时目录；建议选择空间充足的本地 SSD，避免共享网络盘上的逐条索引访问。数据库规模决定临时磁盘需求，运行结束会清理临时 SQLite。每批默认 50,000 条，SQLite 缓存约 64 MiB，不在内存保存全量 ID；扫描全量数据需要时间，日志输出到 stderr。

也可以用 `--row-data /实际路径/row_data` 直接指定输入。输出目录必须不存在，防止混入旧报告；重跑请指定新目录。

## 统计口径

- 默认 `--scope all`：扫描 `row_data/protein_anno` 下所有数据库，包括未被物种树映射引用的目录。残缺数据库没有 FASTA 时会报错，不会静默跳过。
- 如需只统计 1.1.0 流水线所引用的数据库，添加 `--scope mapped`；同一个数据库被多棵树引用只扫描一次。这仍统计该数据库的全部 FASTA，不按树叶子筛选，所以不保证等于最终运行期包中的蛋白数量。
- 可重复传入 `--database archaea232` 等参数，限定数据库。
- 总数是所有选中 FASTA 的蛋白记录数，不按氨基酸序列去重。蛋白身份为 `(数据库名, FASTA header 第一个字段)`；不同数据库的相同 ID 分别计数，同一数据库重复 ID 会报错，需要先解决 ID 歧义。
- 每种注释覆盖率 = 有至少一条该源有效注释且精确匹配 FASTA ID 的蛋白数 / 全部蛋白数 × 100%。重复命中和 `;;` 多注释只计一个蛋白。总体比例按总蛋白数计算，不平均各库百分比。
- 不猜测 ID 前缀、不按 `__gene` 拆分 ID、不自动修复注释。FASTA 文件名和 genome 映射不参与 ID 匹配。
- 沿用 1.1.0 的 tab、空格、逗号、竖线分隔规则，只切分第一次；支持可选表头、BOM、空行和 `#` 注释。注释值中的 `+`、逗号、版本号均保留。无需 annotation_names 文件，也不以名称字典过滤命中。
- 空值及 `-`、`.`、`NA`、`N/A`、`NaN`、`None`、`null` 不算注释（大小写不敏感）。这比流水线把任意非空值视为命中的规则更严格。
- 递归读取 `.faa` 和 `.faa.gz`，支持目录软链接、防循环，并按文件身份去除软/硬链接别名。独立复制的重复文件会触发重复 ID 错误。注释支持 `{cog,kegg,pfam}.tsv` 或 `.tsv.gz`；两者同时存在则报错，不自行挑选。

## 输出与异常

- `coverage.tsv`：各数据库和 ALL 汇总的总蛋白数、各源注释蛋白数、覆盖率及状态。
- `summary.json`：上述结果、缺失注释文件、未匹配行数、异常行数、空注释行数，以及注释重叠统计。未匹配行数是行数，包含重复未知 ID。
- `any_annotated_proteins`：至少有一种注释的蛋白数；`all_three_annotated_proteins`：三种注释均有的蛋白数。`overlap_counts` 使用 COG=1、KEGG=2、PFAM=4 的位掩码，例如 5 表示只有 COG+PFAM，7 表示三者均有，0 表示均未命中。
- 退出码 `0`：统计完成；`2`：报告已生成，但存在缺失文件、未知 ID 或异常行，需要核查；`1`：读取失败、重复 ID、无 FASTA 等致命错误，不生成完整报告。

缺失文件时，该库该源的已观察命中数为 0，分母仍包括其蛋白，因此报告比例仅是已观察覆盖率，不能解释为完整注释结果。出现 `needs_review` 时先检查 JSON 中的问题；缺失、失败和真正零命中并不等价。不要在原始文件仍在写入时运行统计。

脚本参考冻结版 `builders.py` 的递归发现、`runtime_package.py` 的分隔及精确匹配规则，以及 `tools/diagnose_annotation_ids.py` 的软链接去重和表头处理。服务器实际数据未在本地验证。
